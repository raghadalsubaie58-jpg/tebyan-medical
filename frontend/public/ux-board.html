قرارات التصميم الكبرى — Architecture Decision Records
Groq بدل OpenAI
✅ القرار: Groq free tier (Llama 3.3 70B)
لماذا: التكلفة صفر في المرحلة الأولى. السرعة أعلى (~500 tok/s). جودة كافية للتحليل الطبي العربي. OpenAI مذكور كـ optional مدفوع.
EasyOCR بدل Google Vision
✅ القرار: EasyOCR (open-source, local)
لماذا: مجاني تماماً. يعمل محلياً = خصوصية المريض. يدعم العربية. الحد: يحتاج CPU قوي. Google Vision مذكور كـ optional.
Supabase للـ Auth + DB
✅ القرار: Supabase free tier
لماذا: Auth + PostgreSQL + Storage في مكان واحد مجاناً. pgvector جاهز للـ Chat memory. البديل: Firebase (محدود للعربية).
Single Page vs Multi-page
✅ القرار: Hybrid — Landing page + Auth pages منفصلة
لماذا: صفحة رئيسية موحّدة للتحليل + صفحات Auth (/login, /register, /profile, /settings) منفصلة = UX واضح مع بنية قابلة للتوسع.
Dark Mode Anti-Flash
✅ القرار: inline script في <head> + suppressHydrationWarning
لماذا: يمنع وميض اللون الأبيض قبل Hydration. الـ localStorage يُقرأ قبل أي React render. متوافق مع Next.js App Router.
Logo: GitHub LFS → Base64
✅ القرار: embed الـ logo كـ base64 في lib/logo.ts
لماذا: Vercel لا يدعم Git LFS. اللوجو صغير الحجم (PNG). يضمن ظهوره في كل بيئة بدون dependencies خارجية.

01
OCR on Arabic Medical Text — The Hardest Problem
EasyOCR CPU achieves ~70% accuracy on phone-captured lab reports due to font variation, low contrast, and non-standard Arabic medical formatting. PDF text extraction (PyMuPDF) achieves 95% because it reads the embedded digital text directly without image processing.
Status: In Progress Plan: OpenCV deskew + adaptive binarization → target 90%+ Safety: Confidence threshold + user review step before AI analysis
02
Building a RAG Pipeline Without a Medical Corpus
No Arabic clinical guidelines corpus was publicly available, so we built a knowledge base from MedlinePlus and Wikipedia Arabic medical content (2,834 chunks). This is appropriate for patient education, not clinical diagnosis. Context Precision 0.72 — improving with metadata filtering and adaptive chunk sizing.
RAGAS Faithfulness: 0.81 RAGAS Answer Relevance: 0.89 Planned: pgvector migration for persistent embeddings
03
Medical Safety Layer — Zero Diagnosis, Zero Medication
The SafetyAgent in the 5-step pipeline enforces one rule: never diagnose, never prescribe. Every response ends with a referral to a doctor. This was the non-negotiable design constraint from day one. Tested across 10 evaluation questions — 100% compliance. This is the strongest competitive differentiator vs. general LLM chatbots.
Result: 100% safe responses Hallucination Rate: <4% Approach: System prompt + SafetyAgent + response validation
04
Zero-Cost Production Stack — Engineering Constraints as Design Decisions
Every technology choice was driven by one constraint: free tier only. Groq free tier gives 500+ tokens/second — faster than paid OpenAI. EasyOCR runs locally — no API cost, better privacy. ChromaDB in-memory — free but needs pgvector migration for production persistence. This constraint produced a leaner, more privacy-preserving architecture.
